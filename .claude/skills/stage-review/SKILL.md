# stage-review: 단계 종료 의식

CLAUDE.md 규칙 "단계마다 `pnpm verify` 통과 후 보고하고 멈춘다. 단계가 끝나면 리뷰어로 점검한다"를 절차로 만든 것이다.
인자로 단계 이름을 받는다. (예: `2단계 홈·상세·투표`) 없으면 마지막 커밋 이후의 변경을 보고 추정하고, 모르면 묻는다.

## 절차

1. **변경 범위 확정**: `git status --short`와 `git diff HEAD --stat`로 이번 단계 변경을 확인한다. 변경이 없으면 "리뷰할 변경이 없다"고 보고하고 끝낸다.
2. **자동 검증**: `pnpm verify`와 `pnpm build`를 실행한다. 실패하면 **리뷰를 시작하지 말고** 먼저 고친다. (실패한 코드를 리뷰어에게 넘기지 않는다.)
3. **리뷰 호출** (서로 독립적이므로 한 번에 병렬로):
   - `code-reviewer`: 항상 호출한다.
   - `design-fidelity-checker`: UI 파일(`src/shared/ui`, `src/features/*/components`, 화면 `page.tsx`, `globals.css`)이 바뀐 경우에만 호출한다.
   - 각 에이전트에 단계 이름과 중점 영역(이번 단계에서 특히 걱정되는 부분)을 알려준다.
4. **판정 처리**
   - 모든 판정이 PASS면 5로 간다.
   - 하나라도 FIX면 **차단** 항목만 수정하고 2번부터 다시 한다. 같은 단계에서 **최대 2회**까지 재리뷰한다.
   - 2회 후에도 차단이 남으면 멈추고 남은 항목과 이유를 사용자에게 넘겨 판단을 받는다. 임의로 PASS 처리하지 않는다.
   - 권장·참고 항목은 고치지 않고 보고에 그대로 싣는다.
5. **브라우저 확인 안내**: 에이전트가 "시각 확인 필요"로 남긴 항목이 있으면 목록으로 정리한다. 가능하면 개발 서버(`NEXT_PUBLIC_API_MOCKING=enabled pnpm dev`)로 직접 확인하고, 하지 못했으면 확인하지 못했다고 적는다.
6. **종합 보고** 후 **멈춘다.** 커밋과 다음 단계 시작은 사용자 승인 뒤에 한다.

## 보고 형식

```
## N단계 종료 보고
- 자동 검증: verify ✓/✗, build ✓/✗ (테스트 N건)
- code-reviewer: PASS|FIX (차단 n / 권장 n / 참고 n)
- design-fidelity-checker: PASS|FIX|해당 없음 (차단 n / 시각 확인 n)
- 재리뷰: n회
### 고친 것
### 남은 권장·참고
### 확인하지 못한 것   ← 반드시 적는다. 없으면 "없음"
### 다음 결정 (커밋 메시지 초안 포함)
```

## 주의
- 에이전트 정의 파일은 세션 시작 시 로드된다. 이번 세션에서 만든 에이전트는 목록에 없을 수 있다. 호출에 실패하면 다른 에이전트로 대체하지 말고 "리뷰어를 호출하지 못했다"고 보고하고 직접 점검한 범위를 구분해서 적는다.
- 리뷰어는 코드를 수정하지 않는다. 수정은 항상 이 절차를 실행하는 쪽이 한다.
- 이 스킬은 커밋을 만들지 않는다. 커밋은 사용자가 승인한 메시지로 따로 한다.
